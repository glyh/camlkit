# Automatic toplevel printers

## Question

utop installs toplevel printers automatically for values marked
`[@@ocaml.toplevel_printer]`, which is how a library makes its abstract
types print readably. Does that survive linking utop as a library rather
than running its binary?

## Resolution

**It did not. It was silently absent, and this is the third instance of
that failure class**, after implicit bindings and the hermetic spawn flags.

The machinery is `UTop_main.Autoprinter`, an internal submodule, reached
through `UTop_main.execute_phrase`, which wraps `Toploop.execute_phrase`
with a scan before and after. We call `Toploop.execute_phrase` directly, so
nothing ever installed a printer.

Measured against a fixture package carrying the attribute, same library and
same phrase:

| | Result |
| --- | --- |
| real utop | `- : Mylib.t = <mylib holding 5>` |
| our worker, before | `val _0 : Mylib.t = <abstr>` |
| our worker, after | `val _0 : Mylib.t = <mylib holding 5>` |

This matters beyond cosmetics: exploring a codebase is half the stated
purpose, and every type from the project under exploration would have
printed as `<abstr>`.

Reimplemented as `worker/printers.ml`, about thirty lines. Two details were
load-bearing:

- `UTop_compat.ldot` rather than constructing `Longident.Ldot` directly.
  That constructor changed shape in OCaml 5.4, which is exactly why utop
  preprocesses its own sources with cppo, and the floor here is 5.3.
- `UTop_compat.add_cmi_hook` is reachable because `uTop_compat.ml` has no
  `.mli` and the library is `(wrapped false)`. Without that the cmi
  notifications would have been unavailable.

**Only the cmi half is implemented**, covering packages brought in by
`require`. Printers defined inside the session itself need Autoprinter's
`scan_env`, which walks `Env` summaries and is the part most exposed to
compiler-libs churn. Deferred rather than attempted.

The fixture lives at `test/fixtures/mylib`. Its `META` is generated by a
dune rule rather than checked in, because dune treats a source file of that
name specially and will not copy it into the build directory.
